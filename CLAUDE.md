# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это

**Красим кнопки** — приложение на React/Vite: собирает inline-клавиатуры Telegram/MAX, запросы к Bot API и MAX API, размеченный текст сообщений, JSON и вызовы API LEADTEH. Из одной сборки работает и обычным сайтом, и Telegram Mini App. Отдельный Node-бэкенд (`server/`) даёт ИИ-диктовку и аналитику использования, деплоится на свой VPS независимо от фронта.

## Команды

Всё выполняется из корня репозитория.

```bash
npm run dev            # Vite dev-сервер с HMR
npm run build          # tsc -b (типы) + vite build — прогонять перед тем, как считать правку готовой
npm run build:web      # сборка с --base=/ (обычный сайт)
npm run build:miniapp  # сборка с --base=/color_butten/ (для GitHub Pages / Mini App)
npm run lint           # eslint .
npm run preview        # локальный просмотр production-сборки
npm run deploy         # build:miniapp + публикация dist/ в ветку gh-pages — только это видят пользователи Mini App
```

Тестового раннера нет (ни Jest, ни Vitest, ни скрипта `test`). Проверка — `npm run build` (ловит ошибки типов) плюс ручной прогон фичи в `npm run dev`; всё, что видно глазами, смотреть в браузере, а не объявлять готовым по факту компиляции.

Бэкенд запускается отдельно, из папки `server/` и со своими зависимостями:

```bash
cd server && npm install
npm start              # node index.js, порт 8788 и хост 127.0.0.1 по умолчанию
```

Настройки читаются из `server/.env` через `dotenv` (файл не в git, создаётся руками). Чтобы прогнать маршруты, лимит частоты и аналитику, не тратя деньги, положить туда `PORT=8799` и заведомо нерабочий `OPENROUTER_API_KEY=stub`: маршрутизация, 429 и SQLite проверяются полностью, а до OpenRouter такие запросы не доходят. Задавать переменные в командной строке не надо — форма `VAR=значение команда` работает в bash, но не в PowerShell, а рабочая машина по умолчанию на PowerShell. База аналитики при первом запуске создаётся в `server/data/` (папка в `.gitignore`).

### Деплой — прочитать до пуша

Production для Mini App — **GitHub Pages**, а не Vercel, хотя деплой на Vercel тоже существует. На этом уже спотыкались прошлые сессии: `git push` плюс `vercel --prod` обновляет Vercel, а Mini App остаётся на старом коде, потому что Telegram открывает адрес GitHub Pages. Правильная последовательность одна:

```bash
git add <файлы>
git commit -m "Описание на русском"
git push origin main    # Vercel пересоберётся сам — vercel --prod НЕ запускать
npm run deploy          # сборка с --base=/color_butten/ и публикация в gh-pages — вот это видят пользователи
```

Сообщения коммитов — только по-русски, про суть правки, а не перечислением файлов.

Бэкенд `server/` — **отдельная цель деплоя** (свой VPS, свой менеджер процессов): `git push` в этот репозиторий его не обновляет. См. раздел «Бэкенд (`server/`)».

## Архитектура

### Одно состояние в `App.tsx`, вкладки через `hidden`

Всё состояние приложения живёт в `App.tsx` (`useState`/`useMemo`/`useCallback`), данные вниз идут пропсами — ни контекста, ни стора. Вкладки переключаются атрибутом `hidden`.

**Смонтировано не всё — три уровня разные, и это важно при отладке «почему стейт в неактивной вкладке живёт»:**

- Шесть панелей разделов (`keyboard`, `requests`, `formatter`, `json`, `curl`, `leadteh`) отрисованы всегда и только прячутся через `hidden` — их деревья смонтированы постоянно, эффекты продолжают работать.
- **Стартовый раздел — `requests` с Telegram API**, а не первый в списке прямых разделов. Меню «Разделы» группирует API во вложенный уровень: Telegram, MAX и LEADTEH. Разбор curl — самостоятельный раздел, не часть API-конструктора.
- Внутри «Кнопок» ветки платформ взаимоисключающие: `{keyboardPlatform === 'telegram' && …}` и `{keyboardPlatform === 'max' && <MaxKeyboardTab />}` (`App.tsx:224`, `App.tsx:249`) — при переключении платформы неактивная ветка размонтируется и теряет своё состояние.
- Панель аналитики отрисовывается только при `isAdminMode` (`App.tsx:288`) — до разблокировки её в дереве нет вовсе.

```
App.tsx (activeTab, keyboardPlatform, buttons[], showValidation, isAdminMode, launchContext)
  ├── SlideTabs — навигация по вкладкам
  ├── [tab: keyboard]  «Кнопки» — переключатель платформы 'telegram' | 'max'
  │     ├── telegram → AiDictationPanel + GridConstructor (7×7) → ButtonCard[] → Preview → JsonOutput
  │     └── max      → MaxKeyboardTab (самодостаточный)
  ├── [tab: requests] «Запросы» — RequestBuilder, свой внутренний переключатель платформы
  │     ├── telegram → request-builder/TelegramRequestBuilder.tsx
  │     └── max      → MaxRequestBuilder.tsx
  ├── [tab: formatter] «Текст» — TextFormatter
  ├── [tab: json]      «Форматор» — JsonFormatter
  ├── [tab: leadteh]   «API LEADTEH» — LeadtehRequestBuilder (самодостаточный)
  └── [tab: analytics] «Аналитика» — скрытая, в видимом списке вкладок её нет;
        открывается тройным кликом по строке версии в подвале за 1.5 с
        (ADMIN_UNLOCK_CLICKS / ADMIN_UNLOCK_WINDOW_MS в App.tsx) — сознательно не
        URL-параметр, потому что набирать `?admin=1` руками внутри Mini App неудобно
```

`APP_VERSION` в `App.tsx:45` — это же строка, по которой кликают для разблокировки. Она захардкожена и дублирует `version` из `package.json`: при бампе версии править оба места.

### Навигация по вкладкам — `SlideTabs`

Подписи вкладок и их переключение вынесены в `components/SlideTabs/`: горизонтальная лента с затуханием у краёв, автопрокруткой к активной вкладке и стрелками, когда список не помещается. Список вкладок приходит пропом (`tabs`), в него подмешивается «Аналитика», когда включён админ-режим.

Лента снимает не всю проблему тесноты: подписи всё равно держать короткими (`'JSON-форматор'` пришлось сократить до `'Форматор'`). При добавлении или переименовании вкладки проверять ширину 320px.

### Режим запуска — Mini App или веб

`utils/launchContext.ts` определяет, где приложение открыто: по `window.Telegram.WebApp` (`initData`/`platform`) либо по параметрам `tgWebAppData` / `tgWebAppVersion` / `tgWebAppPlatform` в query или hash. Считается один раз через `useMemo` в `App.tsx:63`. От результата зависят две вещи:

- **Веб-шапка** («Веб-версия», заголовок, подзаголовок) рисуется только вне Mini App — внутри Telegram место экономится.
- **Запрет зума** включается только внутри Mini App (`App.tsx:92-118`): подменяется `content` у `meta[name="viewport"]`, вешается класс `mini-app-no-zoom` и перехватываются `gesturestart` / многопальцевый `touchmove`. Обычной веб-версии зум оставлен намеренно, ради доступности — не распространять этот эффект на веб.

### Паттерн «самодостаточный компонент»

`MaxKeyboardTab.tsx` и `LeadtehRequestBuilder.tsx` держат свои типы, состояние и сборку JSON целиком внутри одного файла и намеренно не переиспользуют Telegram-утилиты (`generateJson.ts`, `types/index.ts`). Отсюда следствие: правка `generateJson.ts` на вкладки MAX и LEADTEH не влияет вообще. Расширяя MAX или LEADTEH, повторять эту форму, а не сводить с Telegram-веткой.

`RequestBuilder.tsx` — единственное исключение, которое **разделено** по платформам на файлы: `request-builder/TelegramRequestBuilder.tsx` и `MaxRequestBuilder.tsx`.

### Конструкторы запросов — актуальные цифры

Счётчики методов ниже проверены по коду; при добавлении методов обновлять и здесь.

| Платформа | Методов | Категорий | Где конфиг |
|---|---|---|---|
| Telegram Bot API (до версии 10.1) | 63 | 19 | `src/constants/requestBuilder.ts`, типы `src/types/requestBuilder.ts`, валидация и сборка `src/utils/requestBuilder.ts` |
| MAX API | 31 | 5 | всё внутри `MaxRequestBuilder.tsx` (`MAX_METHODS`) |

Сопутствующее наполнение: `constants/requestPresets.ts` — быстрые подстановки `chat_id` (`{{telegram_id}}`, `-100…`, `@channel`) и координат городов; `constants/requestResponses.ts` — заготовленные примеры ответов Bot API, которые показываются рядом с методом, чтобы человек понимал, что придёт назад.

LEADTEH: base URL `https://app.leadteh.ru/api/v1/{method}?api_token={{token_LT}}`, заголовки показываются информационным баннером, а не в блоке превью; JSON-поля (`filtersJson`, `dataJson`, `fieldJson`) — textarea с `JSON.parse()`, ошибка разбора не блокирует. Новый метод = запись в `LT_METHODS` плюс расширение типа `LeadtehMethod`.

### Разбор curl

«Разобрать curl» — самостоятельный раздел из меню «Разделы»: разбор в `utils/curlParser.ts`, панель в `components/CurlImportPanel.tsx` со своим CSS-модулем. `parseCurl` — чистая функция «строка → объект», про платформы она не знает, поэтому годится и Telegram, и MAX, и LEADTEH; внутрь конкретного API-конструктора её не копировать.

Изначально панель жила на вкладке LEADTEH (коммит `f406b3d`) и переехала сюда по просьбе владельца: curl приходит из документации любой платформы, а не только Leadteh.

- Разбирает переносы строк трёх видов (`\` bash, `^` cmd, «`» PowerShell), фигурные кавычки из статей, флаги `-X -H -d --data-raw --data-urlencode -F -u --url -G`; известные шумовые флаги (`-s -k -L -o` и прочие) пропускает молча, незнакомый флаг съедает вместе со своим значением, чтобы значение не приняли за адрес (`looksLikeUrl`).
- **`safeDecode` разбирает только `%XX` и не превращает `+` в пробел** — в токенах и base64 плюс значащий. Возвращать `replace(/\+/g, ' ')` нельзя, это молча ломает скопированный ключ.
- Блок результата помечен `data-analytics-skip`: там чужие адреса и заголовки из вставленной команды, в аналитику они уходить не должны. Кнопки «Разобрать» / «Пример» / «Очистить» — обычное использование конструктора, они трекаются.
- Тестового раннера в проекте нет; набор проверочных команд гоняли вручную через `node` (`parseCurl` не тянет React и запускается напрямую).

### Правила предметной области (Telegram)

- `generateJson.ts` выдаёт полный `SendMessageBody` (`chat_id: "{{telegram_id}}"`, `text`, `parse_mode`, `reply_markup`), не только разметку клавиатуры.
- Сетка 7×7 (`MAX_GRID_ROWS`/`MAX_GRID_COLS` в `src/constants/index.ts`). Одинаковый `row` — кнопки рядом, разный — друг под другом; внутри строки сортировка по `col` (`groupByRow` в `src/utils/helpers.ts`).
- `style` попадает в JSON только если !== `'default'`; `iconCustomEmojiId` — только если непустое после `trim`.
- `ICON_EMOJI_OPTIONS` (`src/constants/index.ts:19`) — предустановленные ID для `icon_custom_emoji_id`; `ButtonCard` показывает их выпадающим списком плюс режим «Свой ID» для всего остального.
- Валидация ленивая — ошибки рендерятся после первого клика «Скопировать» (`showValidation`), не на каждый ввод.
- Пустой `actionValue` разрешён только у `switch_inline_query` и `switch_inline_query_current_chat` (пустой inline-запрос осмыслен); остальным типам нужно непустое значение.
- В типе `ActionType` восемь вариантов (`src/types/index.ts:3`), в UI реализованы пять — `callback_data`, `url`, `web_app`, `switch_inline_query`, `switch_inline_query_current_chat` (`VALID_ACTION_TYPES` в `App.tsx:22`). Остальные три (`login_url`, `pay`, `copy_text`) в типе есть, интерфейса под них нет.
- Результат ИИ-диктовки для клавиатур (`applyAiTelegramButtons`) **заменяет** `buttons[]` целиком; при дублях `row:col` от модели побеждает последняя кнопка (dedupe через `Map`), координаты зажимаются в 1..7 (`clampGridIndex`).

### Правила предметной области (MAX)

Типы кнопок MAX (`src/types/max.ts`) — `callback`, `message`, `link`, `request_contact`, `request_geo_location`. Общего с Telegram у них ничего нет, включая сборку JSON: см. «Паттерн „самодостаточный компонент“».

### Rich-сообщения (Bot API 10.1) и `TextFormatter`

У `TextFormatter.tsx` четыре режима редактора: `html` и `markdown` (обычное сообщение с `parse_mode`, логика в `src/utils/textFormatting.ts`, копирование склеивает строки через `%0a`) и `rich-html` / `rich-markdown` (`rich_message` из Bot API 10.1, GitHub-style markdown у markdown-варианта). В rich-режиме прячутся обычный тулбар, emoji-пикер, конвертация вставки и `%0a`-вывод — они дают MarkdownV2-синтаксис, несовместимый с rich markdown. Копирование в rich идёт как есть, без `%0a` и без `normalizeTelegramRichHtml`; `validateTelegramRichHtmlCompatibility` выдаёт только мягкие предупреждения и копирование не блокирует. В отличие от обычного HTML, rich HTML **разрешает** `<table>`, `<pre>` и блоки кода — блокировку под них не возвращать.

Справка по rich-разметке (`request-builder/RichMarkupHelp.tsx`) пополняется **только тегами, подтверждёнными официальной докой** `/bots/api#rich-message-formatting-options` — то же правило, что с ID premium emoji: не выдумывать.

Превью в rich-режимах неполное, и это не баг: у `rich-markdown` его нет вообще (GFM-рендерера в проекте нет), у `rich-html` оно подписано «приблизительно, как отрисует браузер» — `<tg-*>` браузер не знает. В конструкторе запросов rich-сообщение собирает `buildInputRichMessage` (`utils/requestBuilder.ts:181`) и кладёт **ровно одно** поле — `html` **или** `markdown`, по `richMessageFormat`. Чекбоксы `is_rtl` и `skip_entity_detection` оформлены карточками `optionGrid`/`optionCard`/`optionHint` с подсказками — новые чекбоксы в этой секции делать так же, а не голым `checkboxRow`.

Панель ИИ-диктовки на этой вкладке умеет и сгенерировать текст с нуля (пустое поле), и разметить уже введённый текст (проп `existingText`, прокинут через `useAiDictation` → `generateFromText` → `POST /api/generate`) — как бэкенд различает эти два сценария, см. «ИИ-диктовка». Панель показывает бейдж текущего режима, чтобы было однозначно, каким синтаксисом придёт результат. Порядок блоков на вкладке (ввод, тулбар, ИИ-панель, свёрнутая справка, превью, копировать/поделиться) переставляли несколько раз по прямой просьбе владельца — архитектурного смысла в нём нет, просто следовать текущему.

### Premium emoji

Синтаксис: `<tg-emoji emoji-id="ID">FALLBACK</tg-emoji>` (HTML), `![FALLBACK](tg://emoji?id=ID)` (MarkdownV2). Данные — `src/constants/premiumEmojiData.ts`, 150 записей без дублей по fallback-символу, ID добыты через `getForumTopicIconStickers` + `getStickerSet?name=TgPremiumIcon`. Обновление: `node scripts/fetch-premium-emoji.mjs BOT_TOKEN`. **ID не выдумывать**: Telegram молча вырезает невалидный `<tg-emoji>`, текст становится пустым и приходит ошибка `message text is empty`.

### ИИ-диктовка (голос → раскладка кнопок или размеченный текст)

`AiDictationPanel.tsx` плюс `useAiDictation.ts` питают кнопку микрофона на вкладках «Кнопки» (обе платформы) и «Текст»: запись через `MediaRecorder` → base64 → `POST /api/transcribe` (распознавание) → редактируемая расшифровка → `POST /api/generate` (генерация) → результат уходит в колбэк `onResult` вкладки и **заменяет** её содержимое целиком (массив кнопок или текст), а не дописывается.

- Провайдер на оба шага один — OpenRouter: `openai/whisper-large-v3` для распознавания, `anthropic/claude-sonnet-4.5` для генерации. У `GenerateMode` (`src/utils/aiClient.ts`) шесть значений: `telegram-keyboard`, `max-keyboard`, `text-html`, `text-markdown`, `text-rich-html`, `text-rich-markdown` — по этому ключу бэкенд выбирает системный промпт.
- Тело запроса может нести `existingText` (осмысленно только для четырёх `text-*` режимов) — тогда бэкенд оборачивает его маркерами `===EXISTING_TEXT_START/END===` и добавляет `===INSTRUCTION===` вокруг расшифровки, а каждый текстовый системный промпт получает указание сохранить содержимое дословно и применить только форматирование. Такие маркеры выбраны потому, что не столкнутся с реальным HTML/Markdown/rich-markdown в тексте пользователя (в отличие от тройных бэктиков или кавычек). Пропсы `existingText`/`modeLabel` у `AiDictationPanel` необязательные именно затем, чтобы две точки вызова из клавиатур (`App.tsx`, `MaxKeyboardTab.tsx`) продолжали работать без них.
- `max_tokens` — 4000 для четырёх текстовых режимов и 2000 для двух клавиатурных: текстовому нужен запас, чтобы вернуть целое существующее сообщение плюс добавленную разметку.
- Запись ограничена 90 с (`MAX_RECORDING_MS`) — держит base64-тело в пределах `client_max_body_size 8m` у nginx и обрывает бесконечные монологи.
- Платные эндпоинты прикрывает лимит частоты (`server/rateLimit.js`), а не CORS: CORS останавливает только кросс-сайтовые вызовы из браузера и границей безопасности не является. Числа и устройство лимита — в разделе «Бэкенд».

## Бэкенд (`server/`)

Самодостаточный Node-процесс (`node:http`, без фреймворка — см. `server/index.js`), развёрнут на своём VPS (`server-main`, не Vercel и не тот же хост, что фронт), за nginx с TLS, под PM2 как `knopki-ai-api`. Полный список эндпоинтов и требуемых переменных окружения — в `server/README.md`, читать до правок кода. Неочевидное со стороны фронта:

- Фронт всегда зовёт **абсолютный** адрес `https://knopki.assaru.space/api/...` (`src/utils/aiClient.ts`), никогда относительный путь: его собственный хост (GitHub Pages) отдаёт только статику и проксировать не может.
- Деплой: `ssh server-main` → `git pull --ff-only` в `/opt/knopki-ai` → `pm2 restart knopki-ai-api`. Файлы на сервере руками не править; `.env` там не в git и `pull` его не трогает.
- Нет `OPENROUTER_API_KEY` — все ИИ-эндпоинты отвечают 500. Нет `ANALYTICS_ADMIN_TOKEN` — `/api/analytics/stats` всегда 401.
- Хранилище аналитики — `node:sqlite` (встроен в Node 22.5+) сознательно вместо `better-sqlite3`: у последнего нет готового бинарника под свежие Node и сборка падает без Visual Studio Build Tools.

### Лимит частоты на платных эндпоинтах

`/api/transcribe` и `/api/generate` тратят деньги владельца ключа OpenRouter, поэтому закрыты лимитом (`server/rateLimit.js`, добавлен 18.08.2026): 30 обращений в минуту и 300 в сутки с одного адреса плюс общий предохранитель 600 в час на весь сервис. Отказ — 429 с `Retry-After` и русским текстом, `aiClient.ts` показывает его как есть. `/api/health` и `/api/analytics/event` лимита не касаются.

- **Проверка стоит в маршрутизации `index.js` до разбора тела** — чужой запрос не тянет в память 8 МБ base64-аудио. Ниже по коду её не переносить.
- **Личность — `X-Real-IP`, и только когда соединение пришло с петлевого адреса**, то есть от своего nginx. `X-Forwarded-For` не годится: первое значение там пишет сам клиент.
- **Счётчики живут в памяти процесса** и верны, пока PM2 держит один экземпляр в режиме fork (`deploy/ecosystem.config.cjs`, `instances` не задан). Появится второй — лимит умножится на их число, счётчики придётся переносить в SQLite рядом с аналитикой. При `pm2 restart` они обнуляются, это принято сознательно.
- **Пределы захардкожены в исходнике**, не в `.env` — так же, как `ALLOWED_ORIGINS`: правка на сервере руками не нужна, всё едет обычным `git pull`.
- `rateLimit.js` — заготовленное место под платную квоту: меняться будет источник личности в `resolveIdentity()` (сегодня IP, завтра проверенный telegram-id из `initData`), контракт `{ allowed, retryAfterSec, scope }` остаётся. Сейчас оба эндпоинта считаются в один счётчик, а квоте понадобится разделение.
- Ключ доступа во фронте защитой не считать: репозиторий публичный, любой секрет в нём виден всем.

### CORS и наблюдаемость

`ALLOWED_ORIGINS` в `server/index.js` — `https://roman72-186.github.io` и `https://telegram-keyboard-constructor.vercel.app`, плюс правило `origin.endsWith('.vercel.app')` для превью-сборок. Новый хост фронта — значит правка этого множества, иначе события аналитики молча не доходят (так и было до коммита 585457f).

`/api/analytics/stats` отдаёт помимо статистики поля `aiRequestsLastHour`, `aiTrackedIdentities`, `aiRejected` — единственный способ заметить стук по платным эндпоинтам, потому что `console.log` в проекте запрещён. `AnalyticsPanel.tsx` рисует только поля, которые знает по имени, лишние игнорирует — добавленное в ответ поле само на экране не появится.

### Что считает аналитика

`src/utils/analytics.ts` подключается в `main.tsx` через `initAnalytics()` и считает только использование самого конструктора. Кнопки, которые пользователь собирает для своего бота, не учитываются — превью раскладки в `Preview.tsx` и подвал помечены `data-analytics-skip`.

- Один делегированный `click`-листенер на `document` (кнопки не оборачиваются): ищет ближайший `<button>`/`[role="button"]` вне `[data-analytics-skip]`; ярлык — `data-analytics-id` → `aria-label` → обрезанный `textContent` (~40 символов) → `id` → `'unknown'`.
- ID сессии — `crypto.randomUUID()` в `sessionStorage` (ключ `analytics_session_id`), один на вкладку браузера.
- Отправка батчем раз в 5 с плюс на `visibilitychange`/`pagehide` через `navigator.sendBeacon`, при отказе — `fetch(..., { keepalive: true })`.
- Pageview шлётся при смене вкладки в `App.tsx`; у «Запросов» свой внутренний переключатель платформы, поэтому оттуда трекается отдельно через проп `isActive` (`pageNameForTab` возвращает для них `null`).

## Визуальная тема

Актуальная тема — **Clean Dark Tool**: тёмный фон, один сдержанный индиго-акцент (`--accent: #5E6AD2` в `src/styles/global.css`), `Geist` для UI-текста, `Share Tech Mono` для моноширинного. Она сменила прежний cyberpunk/neon (cyan-свечение, Orbitron, сканлайны), миграция в коде завершена. `.impeccable.md` — бриф, из которого тема выросла; его принципы полезны (функция важнее атмосферы, один акцент, иерархия пространством, mobile-first, нетехнический пользователь понимает экран за ~10 секунд), а рамка «текущее против нового» там устарела.

Переключателя темы в UI нет: CSS-переменные светлой темы (`[data-theme="light"]`) остались, но `data-theme` не выставляет ничего, кроме inline-скрипта в `index.html`, читающего устаревший ключ `localStorage` от снятого переключателя. Возвращать тему — значит чинить и этот скрипт.

### Кэширование CSS в Telegram Mini App WebView

WebView Telegram кэширует CSS агрессивно и может игнорировать заголовки, поэтому правки переменных цвета текста (`--text-muted`, `--text-dim`) иногда не доезжают до пользователя после деплоя.

**Правило:** критические, всегда видимые цвета текста (placeholder, подписи, подсказки) писать жёстким hex прямо в CSS-модуле, а не через `var(...)`, и дублировать самые важные инлайн в `<style>` внутри `index.html` — он грузится вместе с HTML и отдельно не кэшируется.

```css
color: #88b8d4;             /* ✅ работает даже при кэше */
color: var(--text-muted);   /* ❌ может не примениться в Mini App WebView */
```

Минимальный кегль для любой видимой подписи, включая ярлыки в emoji-пикере, — 11px.

- Никаких `console.log`/`console.error`.
